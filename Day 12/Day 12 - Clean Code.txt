Day 12 - Clean Code :



How Testing Used to Be

-- In the past, unit tests were throwaway code.

> Tests written after production code
> Manual driver programs
> Keyboard-based or visual verification
> Tests deleted after “it works”


Author’s example:

> Timer tested by typing dots
> Waiting 5 seconds
> Watching output replay
> Test thrown away afterward


How Testing Should Be Done Today:

> Modern testing is automated, isolated, and permanent.

- Use mocks instead of real OS dependencies
- Control time instead of waiting
- Verify behavior with assertions
- Tests checked into source control
- Tests evolve with production code


> Uncle bob also mentions that We’ve Improved — But Not Enough

> Agile & TDD increased testing adoption.

> Many programmers now write automated tests.....BUT many miss what makes tests good



-- The Three Laws of TDD --

> TDD is not just “tests first”.

> First Law

-- You may not write production code until you have a failing test

> Second Law

-- You may not write more test code than is sufficient to fail
Not compiling = failing

> Third Law

-- You may not write more production code than is sufficient to pass the failing test
